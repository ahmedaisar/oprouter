# Release and environment record

## Branches and deployment
- Product branch: `main` (GitHub PRs target `main`).
- Production deployment: Vercel project `oprouter`; production URL https://oprouter.vercel.app/.
- Database: Supabase project `cefsewrnmsdqfhlrfomo`.
- PR preview deployments are generated by Vercel. Supabase PR preview branches are currently disabled.

## Migration handling
- Migrations live in `supabase/migrations/` and are applied/verified through the connected Supabase project tooling.
- Before merging a migration, inspect whether Supabase GitHub integration applies migrations on merge; do not assume preview skipped means production migration did not run.
- After migration, verify the ledger, table RLS, function definitions and execute grants.

## CI and release policy
- Fast PR/main CI: lint, typecheck and unit tests. Vercel Git integration handles preview and production builds after merge.
- Comprehensive validation: gateway integration tests and production build in the scheduled/manual/tag-triggered release workflow.
- Do not merge while the required fast checks are pending or red. Before a release, require comprehensive validation too.
- Run independent review on the exact unreleased diff before any deploying push.
- After merge, poll the `main` workflow to completion and verify deployment readiness.
- A successful build is not proof of production database or authenticated behavior.

## Environment caveats
- Vercel has server-side Supabase and OpenRouter environment variable records configured; secret values are masked and have not been independently verified here.
- Supabase migration history through `20261110000500_gateway_rate_limits.sql` was previously applied to the connected development/project database; re-read the migration ledger before another schema change.
- No production signed-in user journey or real provider-backed request has been recorded as verified.
